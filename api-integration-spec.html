Call 1 — Music Brief Generation

Converts the raw user prompt into a structured JSON music brief. This drives both the Apiframe Suno call and, later, the scene manifest generation.

POST /compatible-mode/v1/chat/completions DashScope — OpenAI-compatible
REQUEST HEADERS
HeaderValue
AuthorizationBearer $DASHSCOPE_API_KEY
Content-Typeapplication/json
REQUEST BODY PARAMETERS
ParamTypeRequiredDescription
modelstringrequiredUse qwen-plus for cost efficiency. qwen3.5-plus for higher quality.
messagesarrayrequiredSystem + user message pair. System sets JSON-only output mode.
response_formatobjectrequired{"type": "json_object"} — enforces structured output
temperaturenumberoptional0.4 — low temp for reliable structured JSON
max_tokensintegeroptional800 — enough for the music brief JSON
SYSTEM PROMPT
system prompt 
You are a music production assistant. Given a user prompt describing a song idea,
output ONLY a JSON object (no markdown, no explanation) with this exact schema:

{
  "title": "string — a short evocative song title",
  "genre": "string — primary genre (e.g. pop, hip-hop, cinematic, folk)",
  "subgenre": "string — more specific style (e.g. dark pop, lo-fi hip-hop)",
  "mood": "string — overall emotional tone (e.g. melancholic, euphoric, tense)",
  "bpm_range": "string — estimated BPM range (e.g. 80-90, 120-130)",
  "key": "string — suggested musical key (e.g. C minor, G major)",
  "vocal_style": "string — vocal character (e.g. breathy female, raspy male, choir)",
  "lyric_themes": ["string", "string", "string"],
  "song_structure": ["intro", "verse", "chorus", "verse", "chorus", "bridge", "outro"],
  "duration_seconds": number,
  "suno_style_prompt": "string — a concise style descriptor for Suno (max 200 chars)",
  "suno_lyrics_prompt": "string — a description of the lyric content for Suno (max 300 chars)"
}

Rules:
- duration_seconds should be between 120 and 240.
- suno_style_prompt must describe genre, mood, instrumentation, and vocal style concisely.
- Always output valid JSON. Never wrap in backticks.
FULL REQUEST BODY (Node.js)
javascript 
const generateMusicBrief = async (userPrompt) => {
  const response = await fetch(
    `${process.env.DASHSCOPE_BASE_URL}/chat/completions`,
    {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${process.env.DASHSCOPE_API_KEY}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        model: 'qwen-plus',
        messages: [
          { role: 'system', content: MUSIC_BRIEF_SYSTEM_PROMPT },
          { role: 'user', content: `Create a music brief for: ${userPrompt}` }
        ],
        response_format: { type: 'json_object' },
        temperature: 0.4,
        max_tokens: 800,
      }),
    }
  );

  const data = await response.json();
  const brief = JSON.parse(data.choices[0].message.content);
  return brief; // MusicBrief schema
};

Call 2 — Scene Manifest Generation

Runs after Apiframe returns the completed lyrics. Takes the music brief + lyrics and produces a per-section scene breakdown synced to the song structure.

POST /compatible-mode/v1/chat/completions same endpoint, different system prompt
SYSTEM PROMPT
system prompt 
You are a music video director. Given a music brief and lyrics, output ONLY a JSON 
object (no markdown, no explanation) with this schema:

{
  "song_title": "string",
  "total_duration_seconds": number,
  "scenes": [
    {
      "id": "string — e.g. scene_01",
      "section": "string — e.g. intro, verse_1, chorus_1, bridge, outro",
      "start_seconds": number,
      "end_seconds": number,
      "duration_seconds": number,
      "shot_type": "string — e.g. wide establishing shot, close-up, aerial, tracking shot",
      "location": "string — e.g. mountain ridge at sunset, empty city street, forest clearing",
      "action": "string — what is happening visually in this scene",
      "mood": "string — visual mood / color palette",
      "veo_prompt": "string — a camera-direction prompt suitable for Veo 3.1 (max 300 chars)"
    }
  ]
}

Rules:
- Create one scene per song section.
- Estimate start/end times based on typical section durations for the given BPM and structure.
- veo_prompt must describe the shot in cinematic language: camera movement, subject, lighting, color.
- Scenes must feel like a coherent music video — consistent visual world, escalating energy.
- Output valid JSON only. Never wrap in backticks.
REQUEST BODY (Node.js)
javascript 
const generateSceneManifest = async (brief, lyrics) => {
  const userContent = `
Music Brief:
${JSON.stringify(brief, null, 2)}

Generated Lyrics:
${lyrics}

Create a scene-by-scene visual breakdown for this music video.
`;

  const response = await fetch(
    `${process.env.DASHSCOPE_BASE_URL}/chat/completions`,
    {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${process.env.DASHSCOPE_API_KEY}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        model: 'qwen-plus',
        messages: [
          { role: 'system', content: SCENE_MANIFEST_SYSTEM_PROMPT },
          { role: 'user', content: userContent }
        ],
        response_format: { type: 'json_object' },
        temperature: 0.6,  // slightly higher for creative scene writing
        max_tokens: 2000, // more tokens — 7 scenes × ~250 tokens each
      }),
    }
  );

  const data = await response.json();
  return JSON.parse(data.choices[0].message.content); // SceneManifest
};

Step B — Generate Music

Submit a music generation job using the style prompt from Qwen + the lyrics from Step A. This is the longer async call (~20–30s).

POST https://api.apiframe.pro/suno-music custom_mode = true
ParamTypeRequiredDescription

javascript 
const submitMusicJob = async (brief, lyrics, jobId) => {
  const response = await fetch('https://api.apiframe.pro/suno-music', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': process.env.APIFRAME_API_KEY,
    },
    body: JSON.stringify({
      prompt: lyrics,                         // full lyrics from Step A
      tags: brief.suno_style_prompt,          // style tags from Qwen
      title: brief.title,
      mv: 'chirp-crow',                       // Suno v5
      make_instrumental: false,
      webhook_url: `${process.env.APP_URL}/webhooks/apiframe?jobId=${jobId}`,
      webhook_secret: process.env.APIFRAME_WEBHOOK_SECRET,
    }),
  });

  const data = await response.json();
  return data.task_id;
};

Step C — Polling fallback (if no webhook)
javascript — poll until done 
const pollTaskResult = async (taskId, maxAttempts = 30, intervalMs = 3000) => {
  for (let i = 0; i < maxAttempts; i++) {
    const response = await fetch(
      `https://api.apiframe.pro/fetch/${taskId}`,
      { headers: { 'Authorization': process.env.APIFRAME_API_KEY } }
    );
    const data = await response.json();

    if (data.status === 'finished') return data;
    if (data.status === 'error') throw new Error(`Task failed: ${data.error}`);

    // still processing — wait and retry
    await new Promise(resolve => setTimeout(resolve, intervalMs));
  }
  throw new Error('Polling timeout — task did not complete in time');
};
✓ Prefer webhooks over polling for music generation — Apiframe supports them and they avoid unnecessary HTTP traffic during the 20–30s wait. Use polling only as a fallback for local dev where your localhost isn't publicly reachable.

SongResult schema

Stored after Apiframe completes. Includes MP3 URL and full lyrics for scene generation.

typescript
interface SongResult {
  task_id: string;
  status: 'pending' | 'processing' | 'finished' | 'error';
  title: string;

BullMQ job flow — Feature 1
1
User submits prompt → POST /api/generate
Create a PipelineJobData record with a UUID. Enqueue a BullMQ job. Return { jobId } to the client immediately. Client opens a WebSocket or SSE connection on /api/status/:jobId.
2
Worker: Qwen Call 1 → MusicBrief
Call generateMusicBrief(userPrompt). Store result in job data. Update stage to 'lyrics'. Push progress event to client: "Generating music concept..."
3
Worker: Apiframe lyrics + music — parallel
Fire both submitLyricsJob(brief) and submitMusicJob(brief, ...) concurrently using Promise.all. Store both task_ids in job data. Update stage to 'music'. Push progress: "Composing music and lyrics..."
4
Webhook handler: Apiframe completion
Your POST /webhooks/apiframe?jobId=xxx receives the music payload. Validate x-webhook-secret. Download the MP3 to GCS. Store SongResult in job data. Resume the BullMQ job.
5
Worker: Qwen Call 2 → SceneManifest
Call generateSceneManifest(brief, lyrics). Store manifest in job data. Update stage to 'done'. Push final event to client with { audioUrl, sceneManifest }.
javascript — full orchestrator 
// workers/pipelineWorker.js
import { Worker } from 'bullmq';
import { generateMusicBrief, generateSceneManifest } from './qwen.js';
import { submitLyricsJob, submitMusicJob, pollTaskResult } from './apiframe.js';
import { downloadToGCS } from './storage.js';
import { updateJob, pushProgress } from './jobStore.js';

new Worker('video-pipeline', async (job) => {
  const { jobId, userPrompt } = job.data;

  // ── Step 1: Generate music brief ─────────────────────────
  await pushProgress(jobId, 'Generating music concept...', 10);
  const brief = await generateMusicBrief(userPrompt);
  await updateJob(jobId, { stage: 'lyrics', brief });

  // ── Step 2: Parallel — lyrics + music submission ──────────
  await pushProgress(jobId, 'Composing music and lyrics...', 25);
  const [lyricsTaskId, musicTaskId] = await Promise.all([
    submitLyricsJob(brief),
    submitMusicJob(brief, '', jobId), // lyrics added after Step A completes
  ]);
  await updateJob(jobId, { stage: 'music', lyricsTaskId, musicTaskId });

  // ── Step 3: Poll for lyrics (fast, ~10s) ─────────────────
  const lyricsResult = await pollTaskResult(lyricsTaskId);
  const lyrics = lyricsResult.lyrics;
  await updateJob(jobId, { lyrics });

  // ── Step 4: Wait for music (webhook preferred, or poll) ───
  // If webhook: job is paused here, resumed by webhook handler
  // If polling: uncomment below
  // const musicResult = await pollTaskResult(musicTaskId, 40, 3000);

  // ── Step 5: Download MP3 to GCS ───────────────────────────
  // (runs inside webhook handler, then resumes this job)
  // const storedUrl = await downloadToGCS(musicResult.audio_url, jobId);

  // ── Step 6: Generate scene manifest ──────────────────────
  await pushProgress(jobId, 'Building scene storyboard...', 85);
  const sceneManifest = await generateSceneManifest(brief, lyrics);
  await updateJob(jobId, { stage: 'done', sceneManifest });
  await pushProgress(jobId, 'Ready!', 100);

}, { connection: { url: process.env.REDIS_URL } });
Qwen — Error codes & handling
HTTP CodeErrorAction
400InvalidParameter — messages missing or malformed JSONCheck system prompt for unescaped quotes. Validate JSON output: add "json" keyword to system prompt.
401InvalidApiKeyWrong region key — check DASHSCOPE_BASE_URL matches key region.
429Rate limit exceeded (RPM or RPS)Exponential backoff: retry after 2s, 4s, 8s. Max 3 retries.
500Server errorRetry once after 3s. If persists, fail the job and surface to user.
200finish_reason: "length"Increase max_tokens. Log silently — this truncates JSON output mid-object.
Apiframe — Error codes & handling
Code / StatusMeaningAction
401Invalid API keyCheck Authorization header — value is the raw key, no "Bearer" prefix.

audio_url expiredCDN URL has a short TTLDownload MP3 immediately on webhook receipt — do not store the CDN URL in your DB.
Global retry policy
javascript — exponential backoff wrapper 
const withRetry = async (fn, maxRetries = 3, baseDelayMs = 2000) => {
  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await fn();
    } catch (err) {
      const isRetryable = err.status === 429 || err.status === 500;
      if (!isRetryable || attempt === maxRetries) throw err;
      const delay = baseDelayMs * Math.pow(2, attempt - 1); // 2s, 4s, 8s
      console.warn(`Retry ${attempt}/${maxRetries} after ${delay}ms`);
      await new Promise(r => setTimeout(r, delay));
    }
  }
};

// Usage
const brief = await withRetry(() => generateMusicBrief(userPrompt));
✓ BullMQ has built-in retry support via job options — set { attempts: 3, backoff: { type: 'exponential', delay: 2000 } } on the queue config so failed jobs automatically retry at the queue level as a second layer of protection.
